## 1. 业务背景与使用角色
### 1.1 业务背景

话务中心面向话务员，以事件为中心接收巡查人员通过车辆套件上报的事件。话务员查看证据、判别和补充信息；存在疑问时发起沟通或挂起；确认有效后分配处置资源。已派发事件同步至环卫云平台动态任务跟踪。当前范围仅处理车载监控采样事件，话务中心视角的事件发现类型统一记为人工。

### 1.2 使用角色

| 角色 | 职责 | 数据范围 |
| --- | --- | --- |
| 话务员 | 接收事件、核实判别、补充信息、发起沟通、挂起、分配资源、查看后续流转。 | 已分配或推送至本人处理范围的车载监控采样事件；具体范围待确认。 |
| 任务接收人/处置人员 | 接收环卫云动态任务并现场处置。 | 非本模块直接操作角色。 |

### 1.3 核心目标与价值

| 目标维度 | 说明 |
| --- | --- |
| 及时接收 | 让待判别、待分配阶段的事件进入话务员队列并按优先级呈现。 |
| 快速判别 | 以事件证据和沟通结果支持有效/无效判断及信息补充。 |
| 高效分配 | 基于责任区域、距离和任务量推荐可用资源，并支持人工调整。 |
| 闭环可追踪 | 派发后由环卫云动态任务跟踪事件处置进度。 |

## 3. 功能详细设计
### 3.1 F01 事件接收与队列
#### 3.1.1 功能目标与范围

| 项目 | 说明 |
| --- | --- |
| 功能目标 | 使话务员集中接收并处理待判别、待分配阶段的车载监控采样事件。 |
| 使用角色 | 话务员。 |
| 触发条件 | 接收到符合当前处理范围的事件。 |
| 功能边界 | 不承接监控中心、机器人采样、AI 监控采样、对讲机采样、无人机采样及第三方来源的事件。 |
| 成功结果 | 事件进入对应话务员队列；默认不展开详情，话务员选择事件后进入详情处理。 |

#### 3.1.2 数据与字段规则

| 展示字段 | 业务含义 | 数据来源/口径 | 空值处理 |
| --- | --- | --- | --- |
| 项目名称 | 事件所属项目。 | 上报事件。 | 待确认。 |
| 处理状态 | 话务员工作状态。枚举值：待处理、处理中、挂起中、已完成。 | 话务中心。 | 不可为空。 |
| 处理人 | 成功接单后负责处理该事件的话务员。 | 接单操作。 | 待处理事件为空；处理中、挂起中不可为空。 |
| 接单时间 | 话务员成功开始处理的时间。 | 接单操作。 | 待处理事件为空。 |
| 车牌号 | 上报车辆标识。 | 车载监控采样事件。 | 待确认。 |
| 用户名 | 上报用户/巡查员名称。 | 上报事件。 | 待确认。 |
| 上报时间 | 事件上报时间。 | 上报事件。 | 不可为空。 |
| 事件地点 | 事件标准地点。 | 上报事件。 | 待确认。 |

#### 3.1.3 业务规则与状态变化

| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| --- | --- | --- | --- |
| Q-01 | 事件进入话务中心 | 仅接收事件来源为车载监控采样的事件；事件发现类型统一展示为人工。 | 生成或更新话务员工作项。 |
| Q-02 | 事件状态为待判别 | 事件应进入话务员待处理队列；话务员选择事件卡片或地图事件点仅查看详情，不改变工作状态。 | 事件：待判别；话务员：待处理。 |
| Q-03 | 点击“开始处理” | 话务员选择事件后仅查看详情；点击“开始处理”即确认接单。系统须以原子操作校验事件仍未被接单，成功后记录处理人和接单时间，在事件信息标题右侧展示该信息，并开放补充信息、语音通话、派发任务、标记无效和挂起操作。 | 话务员：待处理→处理中；处理人、接单时间写入。 |
| Q-04 | 事件已派发 | 话务员工作结束；后续现场处置不再占用默认待办队列。派发成功后列表自动切换至待处理队列，不保留当前事件选择。 | 事件：待处理；话务员：已完成；当前队列：待处理；当前选中事件为空。 |
| Q-05 | 收起事件列表 | 话务员可通过左侧队列的收起按钮折叠或展开事件列表；列表不提供自动轮播或暂停轮播操作。 | 不改变队列数据、事件状态或当前选中事件。 |
| Q-06 | 切换事件卡片 | 根据当前事件关联的巡查片区，刷新该片区的模拟巡查范围、轨迹、巡查车位置、事件坐标和资源推荐数据；地图左上角不展示项目事件摘要卡片。 | 地图视野定位至当前片区；项目名称、巡查员及事件地点等信息以左侧事件列表和右侧事件详情为准；详情与资源候选数据同步至当前事件。 |
| Q-07 | 事件挂起 | 仅当前处理人可挂起事件；挂起后仍归该处理人，不支持释放、转交或由其他话务员重新接单。挂起中不提供恢复处理按钮，直接保留后续处理入口。 | 话务员：处理中→挂起中；当前队列：挂起中；保留处理人、接单时间和当前事件选择；实际发起后续处理时自动回到处理中。 |
| Q-08 | 并发接单 | 多名话务员同时开始处理同一事件时，系统仅允许最先提交成功的一人接单；其他人不产生任何处理操作。 | 接单失败方提示“该事件已被 XX 接单”，并刷新事件状态和处理人。 |

#### 3.1.4 交互流程
1. 系统加载当前话务员处理范围内的车载监控采样事件。
2. 系统按话务员工作状态归入待处理、处理中、挂起中、已完成队列，并应用第 4.2 节排序规则。
3. 默认不展开事件详情。话务员选择事件卡片或地图事件点仅展开详情并保留待处理；待处理详情仅展示“开始处理”按钮。点击成功后，话务员工作状态变为处理中，在事件信息标题右侧展示处理人和接单时间，并开放后续处理操作。
4. 话务员可收起左侧事件列表扩大地图视野；收起或展开不影响事件选择。选择事件卡片时，地图切换至该事件所属片区的模拟位置和业务图层。
5. 成功：列表、详情、地图和资源候选同步刷新；失败：保留当前列表并提示接收或加载失败原因。
#### 3.1.5 异常处理

| 异常场景 | 系统处理 | 用户反馈 | 恢复方式 |
| --- | --- | --- | --- |
| 无符合范围的事件 | 展示空状态。 | 提示当前暂无待处理事件。 | 保持工作台打开，等待新事件。 |
| 事件数据加载失败 | 不改变已有队列数据。 | 提示加载失败。 | 重新加载。 |
| 并发开始处理 | 不覆盖已接单事件的处理人或处理记录。 | 提示该事件已被其他话务员接单，并刷新事件详情。 | 选择其他待处理事件或查看最新状态。 |

### 3.2 F02 事件详情与判别
#### 3.2.1 功能目标与范围

| 项目 | 说明 |
| --- | --- |
| 功能目标 | 让话务员依据事件原始信息和图片证据完成判别或补充信息。 |
| 使用角色 | 话务员。 |
| 触发条件 | 在事件队列中选择事件。 |
| 功能边界 | 不提供车辆运行状态检查。详情不显示顶部标题，关闭按钮悬浮于右上角且不占用内容高度；详情依次展示事件信息、事件证据、补充信息及派发信息/通话记录，不展示状态环节图或派发/通话区域标题；事件证据区仅展示原始图片或视频，不展示状态字段；事件信息展示发生时间、发现方、地点和关联任务，不展示当前状态，其中发生时间以整行等宽数字字段完整展示。详情区直接显示派发信息与通话记录标签，默认展示派发信息，可切换通话记录；派发信息仅展示处置人员、协同车辆和派发时间；通话记录展示呼叫时间、方向、结果、时长和通话参与人，非已完成任务支持回拨，不展示通话内容。已完成任务详情为只读，隐藏补充信息操作及底部操作栏中的语音通话、派发任务、标记无效、挂起和更多操作。事件性质、类型和描述仅在补充信息表单及补充信息字段组中呈现，不展示发现类型、事件来源、经纬度或补充记录。 |
| 成功结果 | 有效事件进入待分配；无效事件直接闭环；补充信息保存至事件。 |

#### 3.2.2 数据与字段规则

| 字段 | 业务含义 | 数据来源/取值规则 | 空值处理 |
| --- | --- | --- | --- |
| 事件发生时间 | 事件实际发生或上报记录的发生时间。 | 上报事件。 | 待确认。 |
| 事件发现方 | 具体的人、车或设备，例如巡查员张三、独角兽 10032、摄像头 A。 | 上报事件。 | 待确认。 |
| 事件图片 | 事件证据图片。 | 上报事件。 | 待确认。 |
| 图片预览操作 | 在图片预览中发起补充、派发或无效闭环。 | 仅当前处理人且事件处于处理中或挂起中时可操作；未接单、已完成或无效事件仅提供查看。补充信息和标记无效表单在预览图片右侧展开，派发任务复用资源派发流程。 | 不可操作时隐藏预览底部的全部处理按钮。 |
| 事件地点 | 事件标准地点。 | 上报事件。 | 待确认。 |
| 详细地点 | 具体点位或地址补充。 | 上报事件。 | 待确认。 |
| 关联任务 | 派发后关联的环卫云动态任务。 | 环卫云平台。 | 未派发时为空。 |
| 派发信息与通话记录 | 事件关联的派发信息及通话记录，通过标签切换展示。派发信息仅含处置人员、协同车辆、派发时间；通话记录含呼叫时间、方向、结果、时长和通话参与人，非已完成任务可回拨。 | 通讯服务、资源派发及环卫云平台。 | 通话记录为空时提示暂无通话记录；派发字段暂无数据时显示 --；已完成任务不展示回拨操作；不展示通话内容。 |
| 补充信息 | 单次保存的具体补充字段。有效事件展示事件性质、事件类型、事件描述；无效事件仅展示事件性质。 | 话务员补充或图片判读。 | 未补充时提示暂无补充信息；不展示时间、来源或历史补充记录。 |

| J-05 | 保存并派发任务 | 保存有效事件的已填写补充字段后，直接打开资源推荐与派发界面；补充信息卡只展示已填写字段，不生成补充记录。 | 事件维持待分配，进入分配操作。 |
| J-06 | 查看已完成任务详情 | 已完成任务详情仅供查看，隐藏补充信息操作和底部操作栏，不提供语音通话、派发任务、标记无效、挂起、更多或通话记录回拨操作。 | 无。 |
| J-07 | 在图片预览中处理事件 | 仅当前处理人且事件处于处理中或挂起中时，预览底部提供补充信息、派发任务、标记无效；未接单事件不展示上述按钮。补充信息与标记无效在图片右侧以表单面板展开。派发任务不经过补充信息表单，直接复用资源推荐与派发界面。 | 与详情内同名操作保持一致：保存补充后刷新详情，标记无效后闭环，派发后进入资源派发。 |

#### 3.2.4 交互流程
1. 话务员进入详情后查看事件原始信息、图片、补充信息及派发信息；可直接通过派发信息、通话记录标签切换查看通话记录，并从记录回拨原参与人。
2. 话务员点击“补充信息”时，默认选中有效事件；问题类型和事件描述可留空，问题类型默认不选中。问题类型按一级分类与二级问题级联选择，一级分类包含环境卫生、市容秩序、设施容貌，选择一级分类后展示对应二级问题；保存结果以“一级分类 / 二级问题”展示。补充结果仅展示已填写字段，不展示时间、来源或历史记录。有疑问时可进入沟通或挂起流程。
3. 话务员点击“派发任务”时，系统不打开补充信息弹窗，默认判别为有效事件并直接进入资源选择；也可在补充信息弹窗中选择“保存并派发任务”。判别无效时，隐藏问题类型、事件描述和“保存并派发任务”，仅展示红色“确认闭环”以完成闭环。
4. 成功：保存补充信息并刷新详情、队列和流转信息；失败：保留已输入内容并提示失败原因。
5. 话务工作状态为已完成时，详情仅展示已留存的信息和记录，不展示任何处理操作或通话回拨入口。

### 3.3 F03 沟通与挂起
#### 3.3.1 功能目标与范围

| 项目 | 说明 |
| --- | --- |
| 功能目标 | 为信息核实和资源确认提供通话入口，并防止等待中的事件被遗漏。 |
| 使用角色 | 话务员。 |
| 触发条件 | 事件信息不清楚、需要向巡查员核实，或需要与候选资源确认。 |
| 功能边界 | 支持话务员主动发起单人及群组语音通话，并接听巡查员事件关联型或普通来电；选择成员以弹窗承载，打开时默认预选当前事件的巡查上报人。通话建立后以成员卡片网格承载会中管理，可继续添加或移除成员、控制单个成员麦克风、对其他成员全员静音，并可收起为地图悬浮通话条。通话结束后保存一条统一记录，包含呼叫时间、方向、业务关联、通话结果、时长和参与人；事件呼入、事件外呼关联原事件，普通通话不自动关联前台事件；不采集或展示通话内容。车辆是否可作为通话对象仍待确认。 |
| 成功结果 | 沟通结论可用于补充事件信息或资源选择；挂起事件即时进入挂起中队列并持续统计挂起时长。 |

#### 3.3.2 数据与字段规则

| 字段 | 业务含义 | 数据来源/取值规则 | 空值处理 |
| --- | --- | --- | --- |
| 沟通对象 | 巡查员/上报人或候选人员。 | 当前事件、候选资源及通讯录。 | 至少选择一名人员；支持多选建立群组通话。 |
| 项目组织通讯录 | 当前项目内可选的沟通人员及其组织归属。 | 项目组织服务；上报人取当前事件发现方。 | 打开选择面板时默认选中巡查上报人；其他人员按组织分类展示，可按姓名、项目、组织或岗位搜索；无搜索结果时不清空已选人员。 |
| 群组成员数 | 同一通话中被选中的人员数量。 | 沟通对象选择结果。 | 至少 1 人；车辆通话能力待确认。 |

| 麦克风状态 | 人员在当前通话内的发言状态。 | 话务员对本人或单个沟通对象的静音/解除静音操作；全员静音仅作用于其他沟通对象。 | 默认为麦克风正常；会话结束后不保留为人员固定状态。 |
| 通话记录 | 统一呼叫记录的时间、方向、业务关联、结果、时长与参与人。 | 通讯服务在通话结束时写入。 | 无记录时提示暂无通话记录；不保存或展示通话内容；可回拨原参与人。 |
| 挂起时长 | 自事件进入挂起中起累计的时长。 | 系统按挂起时刻实时计算，并在挂起中队列卡片的“挂起中”标签后展示为“已挂起{N}min”。 | 不可为空。 |

#### 3.3.3 业务规则与状态变化

| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| --- | --- | --- | --- |
| C-01 | 开始沟通 | 仅当前处理人可打开通话选择界面和开始语音通话；挂起中发起通话时，系统直接继续处理并开始通话，不单独提供恢复处理步骤。单人发起单人通话，多人发起群组通话。 | 记录参与成员和通话记录；挂起中→处理中。 |
| C-02 | 挂起事件 | 仅当前处理人可在信息不足、等待车端回复或等待确认时挂起；点击“挂起”后不弹出确认或设置窗口，系统立即记录挂起时刻并完成状态流转。挂起中仍直接展示补充、通话、派发、标记无效等可操作入口，不展示“恢复处理”按钮。 | 话务员：处理中→挂起中；事件保持待判别或待分配；保留处理人、接单时间和当前事件选择；实际发起后续处理时自动回到处理中；当前队列：挂起中。 |

| C-04 | 通话进行中收起窗口 | 沟通对象默认在居中弹窗中选择；通话持续进行时，话务员可将窗口收起为地图上的悬浮通话条，并随时展开或结束通话。 | 不改变事件状态、参与成员、麦克风状态和通话计时。 |
| C-05 | 会中成员管理 | 话务员可在通话成员网格中继续添加通讯录人员或移除单个沟通对象；移除最后 1 名沟通对象时阻止操作并提示。 | 成员计数、通话成员网格和悬浮通话条名称同步更新；不改变事件状态。 |
| C-06 | 会中麦克风管理 | 话务员可对本人或单个沟通对象静音/解除静音，也可对其他沟通对象执行全员静音/解除。 | 仅更新当前会话的麦克风状态；不改变事件状态、成员关系或人员固定设置。 |

#### 3.3.4 交互流程
1. 当前处理人在事件详情或资源候选列表中打开语音通话弹窗；系统默认选中巡查上报人，并按当前项目组织展示其他人员。话务员可按姓名、项目、组织或岗位搜索后选择一名或多名沟通对象。
2. 系统按选择人数发起单人或群组语音通话，并以成员卡片网格展示当前话务员和沟通对象。
3. 通话期间，话务员可添加或移除成员，对本人或单个成员静音/解除静音，或对其他成员执行全员静音；成员数、状态和悬浮通话条名称同步刷新。
4. 话务员可将通话收起为地图悬浮通话条，再展开继续管理成员或结束通话。
5. 通话结束后系统统一留存呼叫时间、方向、业务关联、结果、时长和参与人，同次通话仅一条记录；话务员可在详情或通话弹窗中查看记录，并通过回拨预选原参与人。
6. 话务员依据沟通结论继续补充事件信息、选择资源，或直接点击“挂起”将事件挂起。
7. 系统即时记录挂起时刻并将事件移入挂起中队列；挂起中卡片在状态标签后展示“已挂起{N}min”和处理人，当前事件保持归属给原话务员，详情直接保留可继续执行的处理操作；发起通话、保存补充或派发时自动回到处理中。
8. 成功：提示操作成功并刷新对应队列；失败：不改变原工作状态并提示失败原因。
#### 3.3.5 异常处理

| 异常场景 | 系统处理 | 用户反馈 | 恢复方式 |
| --- | --- | --- | --- |

| 移除最后一名沟通对象 | 阻止移除。 | 提示通话中至少保留一名沟通对象。 | 保留当前成员或直接结束通话。 |
| 通讯服务不可用 | 不改变事件状态和补充信息。 | 提示通讯不可用。 | 重试或改用后续确认的沟通方式。 |

#### 3.4.5 交互流程
1. 话务员对待分配事件发起分配，系统在工作台侧栏以图标返回和“资源派发”标题呈现，默认加载统一候选资源池，地图保持可见并显示以事件为中心的 300m 范围圆。
2. 系统按责任区域、当前距离、当前任务量排序，默认将首个推荐资源加入顶部已选资源；人员与车辆候选卡均采用既有左右分区结构，并提供联系、添加操作。
3. 所有资源筛选组统一展示搜索、人员/车辆、“显示在线”和派发范围；“显示在线”默认勾选，话务员取消后可查看满足其他条件的在线及离线候选资源。
4. 话务员可输入派发范围或拖动地图圆形边界调整半径，并可组合其他筛选条件；系统同步刷新候选列表和地图候选点。话务员可从资源卡片或地图点位添加任意多项资源，已选资源置于候选列表上方并支持移除，任何筛选变化均不清空已选资源。
5. 话务员确认派发后，系统创建动态任务并关联事件；成功后刷新事件状态和话务员队列，自动切换至待处理队列并清空当前事件选择，失败时保留选择结果并提示失败原因。

#### 3.8.5 交互流程
1. 运营调度工作台收到来电请求，在地图右上角电话图标显示等待数量，并展开来电浮层。
2. 用户可在“全部、事件来电、普通来电”之间筛选，也可点击电话图标重新打开已自动收起的列表。
3. 用户点击请求卡片，系统校验请求仍为等待中；校验失败时提示请求已失效并刷新列表。
4. 系统按请求类型处理：事件来电执行事件定位和前台事件状态联动；普通来电保持当前事件上下文。
5. 若存在旧通话，系统先结束并写入旧通话记录，再建立新通话；建立失败时新请求恢复为等待中并提示失败原因。
6. 通话结束后统一写入一条记录；事件视图按关联事件筛选同一条记录，普通通话不自动关联当前事件；请求状态变为已结束。超时未接、取消或失败请求也留存相应结果，未接通时长显示“—”。

| 关联事件不存在 | 事件来电携带的事件 ID 无法匹配 | 请求标记为已取消，不改变其他事件。 | 提示无法定位关联事件。 | 等待巡查员重新发起。 |

### 3.9 F09 统一通话记录
#### 3.9.1 页面布局

#### 3.9.2 查询筛选区
| 条件 | 规则 |

| 业务关联 | 枚举值：全部关联（默认）、事件通话（存在事件 ID）、普通通话（无事件 ID）。 |
| 通话结果 | 枚举值：全部结果（默认）、已接通、未接听、已取消、呼叫失败。接通后被新来电打断仍为已接通，另记结束原因。 |
| 时间范围 | 使用开始日期和结束日期两个日期控件，均为空时表示全部时间；按呼叫时间的自然日闭区间筛选，支持仅填写一端。 |

#### 3.9.3 数据列表区
| 字段 | 展示与口径 |
| --- | --- |

| 时长 | 从接通起累计，以 min 为单位，秒数除以 60 后保留两位小数；列表表头为“时长(min)”，如 02:36 显示 2.60；事件详情及通话弹窗记录显示“2.60 min”；已接通可为 0.00，未接通显示“—”。 |

| 记录身份 | 每个呼叫尝试具有唯一 ID，事件视图只筛选统一记录，同一通话不重复留存；回拨为新尝试并生成新 ID。 |

| 查看关联事件 | 当前话务员 | 点击编号关闭记录弹窗并定位原事件，切换通话记录标签；不触发接单或挂起恢复；事件不存在时提示并保留记录弹窗。 |
| 事件记录回拨 | 当前事件处理人 | 仅原事件处于本人处理中或挂起中且当前无通话时可用；先预选原参与人，由话务员确认后呼出；已完成事件只读。 |
| 普通记录回拨 | 当前话务员 | 当前无通话时可用，复用原项目通讯录预选原参与人，确认后发起普通外呼，不切换或关联前台事件。 |
1. 打开记录后查询当前话务员的统一记录；筛选和翻页不改变事件状态。
2. 来电接通、事件外呼及普通回拨结束后，各写入一条统一记录；事件详情、通话弹窗和统一查询同步更新。
3. 等待超过 60 秒自动留存未接听结果并移除待接角标；取消和失败结果由通讯服务回传，原型提供相应示例数据。
4. 回拨先显示对象选择，再由用户确认发起；新通话使用新记录 ID，保留原业务关联。失败时保留可继续操作的界面并提示原因。

## 4. 业务规则汇总
### 4.1 事件范围与来源口径

| 规则项 | 规则 |
| --- | --- |
| 事件来源范围 | 话务中心仅处理车载监控采样事件，巡查车归入该来源。 |
| 事件发现类型 | 话务中心处理的事件统一记为人工。 |
| 非范围来源 | 监控中心、机器人采样、AI 监控采样、对讲机采样、无人机采样、第三方来源不在当前范围。 |

### 4.2 状态流转与队列排序

```text
事件：待判别 -> 待分配 -> 待处理 -> 处理中 -> 待核查 -> 已完成
话务员：待处理 -> 处理中 -> 挂起中（等待） -> 处理中 -> 已完成
有效判别：待判别 -> 待分配；分配成功：待分配 -> 待处理，话务员 -> 已完成
无效判别：事件直接闭环（最终状态口径待确认）
```

查看事件卡片或地图事件点仅打开详情，不触发状态流转；仅点击“开始处理”成功后，话务员工作状态由待处理变为处理中，并记录处理人和接单时间。

事件挂起后切换至挂起中队列并保留当前处理人；派发成功后，话务员工作项完成，界面回到待处理队列并恢复地图概览态。

| 话务员队列 | 排序规则 |
| --- | --- |
| 待处理 | 高优先级事件在前，再按上报时间升序；高优规则为项目名称与问题类型的命中组合。 |
| 处理中 | 高优先级事件在前，再按上报时间倒序。 |
| 挂起中 | 高优先级事件在前，再按挂起时长降序。 |
| 已完成 | 按话务完成时间降序。 |

**高优规则配置**：事件上报时，系统按后台配置的高优规则自动判定优先级——高优规则分为两个维度：**重点项目**与**重点问题类型**，事件命中其中任一维度即视为高优先级（OR 逻辑）；未命中的事件均为普通优先级。命中高优的事件在待处理、处理中、挂起中队列中优先排序。两个维度在后台「高优规则配置」页分别维护清单（支持添加、删除、恢复默认），存量事件在进入工作台时按当前配置自动重算。

### 4.3 分配规则

| 规则项 | 规则 |
| --- | --- |
| 推荐主体 | 默认将系统排序后的首个推荐资源加入已选资源；统一候选区支持人员和车辆分类，其中人员按当前项目组织分组，车辆按车型分组。 |
| 候选依据 | 推荐资源结合人员、车辆在线情况；统一候选资源范围限定为当前项目可分配资源池及派发范围圆内，并受搜索、人员/车辆和“显示在线”共同过滤。 |
| 排序顺序 | 责任区域 → 当前距离 → 当前任务量。 |
| 人工调整 | 资源卡展示名称、任务数、岗位、在线状态、距离和预计时间，并提供图标化联系、添加操作；话务员可添加多项人员和车辆，所有资源筛选组统一提供搜索、人员/车辆、“显示在线”和派发范围。“显示在线”默认勾选。人员分组与语音通话的当前项目通讯录组织一致；车辆分组包括洗扫车、洒水车、独角兽等车型。 |

| 空间联动 | 资源派发期间地图以事件为中心展示范围圆、范围内候选资源及当前已选资源；范围支持输入或拖动调整，候选列表与地图点位同步过滤，每项已选资源展示与事件的路线预览及 ETA。 |

### 4.4 数据补充与闭环规则

### 4.5 来电请求规则

| 规则项 | 规则 |
| --- | --- |
| 请求类型 | 来电请求分为事件关联型和普通型；事件关联型必须携带事件 ID，普通型不关联事件。两类请求在运营调度地图右上角同一列表中展示并支持按类型筛选。 |
| 接听范围 | 请求按巡查片区固定路由至负责该片区的话务员，不支持其他话务员抢单、转交或从事件列表任意创建来电。 |

| 重复请求 | 同一事件的重复来电合并为一条等待项，保留最新请求时间和请求次数。 |
| 已闭环事件 | 事件来电即使关联事件已完成或无效，也允许建立本次来电，但仅提供只读事件上下文，不重新打开事件处理流程。 |

## 8. 验收标准
- [ ] 运营中心框架的“品质运营”分组仅展示“运营调度”和“调度记录”，不展示“规则配置”；两个保留入口可正常切换对应的嵌入内容。
- [ ] 工作台右上角提供“后台管理”入口，可进入事件记录明细后台；后台页可返回工作台。
- [ ] 后台可按项目名称、车牌号、关联巡查员、品质运营专员、发生时间范围、接单时间范围和处理状态进行单项或组合查询；关联巡查员支持输入姓名关键字并通过查询按钮或回车执行包含式模糊匹配，重置后清空该条件。
- [ ] 查询条件无法在一行完整展示时，默认仅显示一行并支持展开或收起更多条件；查询、重置和导出按钮始终在同一操作行，不提供导入入口。
- [ ] 列表展示规定字段（含接单时间），支持单选、当前页全选、分页及导出记录；未选择记录时导出按钮不可用。
- [ ] 点击列表“查看”后，详情弹窗左侧展示事件、补充和派发信息，右侧按事件发生顺序展示操作时间轴；每条日志仅含日期、时间、操作人和操作行为。
- [ ] 仅车载监控采样事件可进入话务中心；详情中的发现类型为人工、事件来源为车载监控采样。
- [ ] 事件卡片展示项目名称、话务员处理状态、车牌号、用户名、上报时间和事件地点；处理中、挂起中卡片在状态标签后展示处理人。
- [ ] 事件详情展示本 PRD 第 3.2.2 节已确认字段，不展示状态环节图。
- [ ] 事件详情不展示顶部标题、状态环节图及派发/通话区域标题；发生时间整行完整显示；处理人和接单时间直接集成在事件信息标题右侧、不展示独立字段名；事件证据区和事件信息区不重复展示状态字段；派发信息默认展示并可切换至通话记录。
- [ ] 选择已完成任务时，详情不展示补充信息操作、派发任务、标记无效、更多、语音通话、挂起或通话记录回拨入口；已留存信息和记录仍可查看。
- [ ] 待判别事件进入话务员待处理队列；查看事件卡片或地图事件点后仍保持待处理，详情仅展示“开始处理”按钮；点击成功后记录处理人和接单时间，事件变为处理中，并开放补充、通话、派发、标记无效和挂起操作。
- [ ] 待处理、处理中、挂起中、已完成队列按第 4.2 节规则排序。
- [ ] 点击详情底部“挂起”后不弹出原因、提醒时间或二次确认窗口，事件立即进入挂起中状态；挂起中卡片在状态标签后以“处理人 + 已挂起{N}min”展示并每分钟更新累计时长。
- [ ] 挂起事件仍归原处理人，当前队列切换为挂起中；详情直接展示补充、语音通话、派发任务和标记无效等可操作入口，不展示“恢复处理”按钮；发起通话、保存补充或派发时自动回到处理中。确认派发成功后，事件卡片列表自动切换至待处理队列，不选中任何事件，详情与资源派发侧栏关闭且地图恢复概览态。
- [ ] 点击派发任务时不打开补充信息弹窗，事件默认判别为有效事件并进入资源派发。
- [ ] 仅当前处理人且事件处于处理中或挂起中时，可在事件图片预览中使用补充信息、派发任务和标记无效操作；未接单、已完成或无效事件预览中不展示任何处理按钮。点击补充信息或标记无效时，表单在图片右侧展开，点击派发任务时直接进入既有资源派发流程；三项操作与详情内同名操作的状态变化一致。
- [ ] 点击补充信息时仅默认选中有效事件；问题类型和事件描述均可为空，问题类型默认不选中；问题类型选择为一级分类与二级问题的级联流程，切换一级分类后清空二级问题，保存结果展示完整层级。
- [ ] 补充信息卡仅展示一次补充的实际填写字段，不展示时间、来源或补充记录。
- [ ] 选择无效事件后，补充信息弹窗不展示问题类型和事件描述，保存时不写入这两个字段并完成闭环。
- [ ] 无效事件执行直接闭环；最终事件状态按确认后的口径保存。
- [ ] 当前处理人能够在弹窗中选择一名或多名人员发起单人或群组语音通话；通话中以成员卡片网格展示，支持继续添加、移除、单人静音/解除静音和其他成员全员静音；通话可收起为地图悬浮通话条。
- [ ] 从事件详情打开通话对象选择时，当前巡查上报人默认已选；其他可选人员按当前项目组织分类展示，支持按姓名、项目、组织或岗位搜索，搜索筛选不清空已选人员。
- [ ] 资源派发侧栏顶部展示带箭杆和箭头方向轨迹的返回事件详情图标，悬停和按压时提供边界、阴影与位移反馈；图标与“资源派发”标题通过细分隔形成稳定层级。内容区合并推荐资源与自主选择资源，顶部展示已选资源，默认加入首个推荐资源且允许移除；下方展示统一候选资源池。
- [ ] 资源派发按责任区域、当前距离、当前任务量排序展示推荐资源；人员与车辆候选卡展示名称或车牌、岗位、当日待完成、在线状态、距离和预计时间，联系、添加操作保持不变；所有资源筛选组统一提供搜索、人员/车辆、“显示在线”和派发范围，“显示在线”默认勾选，取消后展示满足其他条件的在线及离线资源。人员按当前项目组织分组，车辆按车型分组，调整筛选不清空已选资源。
- [ ] 人员和车辆均支持多选；已选资源置于候选列表上方并支持移除。派发期间地图以事件为中心展示默认 300m 范围圆；用户可在所有资源筛选组输入半径或拖动圆形边界调整范围，候选列表和地图候选点同步展示符合全部条件的资源，筛选变化不清除已选资源；地图持续展示每项已选资源至事件的路线预览及 ETA，列表与地图点位可双向选择。
- [ ] 分配成功后，事件转为待处理、话务员工作项转为已完成，并在环卫云生成关联动态任务。
- [ ] 派发信息仅展示处置人员、协同车辆和派发时间，不展示派发状态、任务状态、待派发/待判别信息或说明文字；关联任务在事件信息区展示。
- [ ] 详情与通话弹窗中的通话记录统一展示呼叫时间、方向、结果、以 min 为单位的时长和全部通话参与人姓名，不展示通话内容；仅当前处理人可从任一记录回拨，系统预选原参与人后进入通话选择界面。
- [ ] 默认进入工作台时，所有事件卡片与地图事件点均未选中；地图仅展示可点击事件点，不显示事件摘要、巡查车当前位置、巡查轨迹或巡查上报范围。
- [ ] 选中事件卡片或地图事件点后，地图加载对应事件的巡查车当前位置、巡查轨迹和巡查上报范围，但左上角不展示项目名称、项目经理、巡查员、上报时间及事件地点摘要卡片；地图容器不加载 SVG 覆盖图形。
- [ ] 左侧事件列表可收起和展开，且页面不存在事件轮播或暂停轮播操作。
- [ ] 切换不同巡查片区的事件卡片时，地图位置、事件点、巡查车位置、轨迹、上报范围及资源推荐模拟数据随当前事件同步切换。
- [ ] 地图右上角提供电话请求图标；等待请求显示数量角标，通话中显示通话状态；入口不依赖事件接收开关。
- [ ] 事件关联型和普通来电统一进入来电列表，可按全部、事件来电、普通来电筛选；来电卡片仅展示项目、车牌号、巡查员姓名和请求时间，不展示事件类型、事件地点、片区、岗位或“未关联事件”等字段。
- [ ] 来电浮层无操作约 9 秒后自动收起，等待请求仍保留；点击电话图标可重新展开；请求等待超过 60 秒后自动标记为已超时并移除等待角标。
- [ ] 点击事件关联型来电后自动选中关联事件；若当前前台是其他处理中事件，仅自动挂起该前台事件；待处理目标事件自动接单，挂起目标事件自动恢复。
- [ ] 点击普通来电后不切换事件、不改变当前事件状态、不关闭详情、图片预览或资源派发上下文；通话记录独立保存。
- [ ] 同一工作台同一时间仅允许一场通话；接听新来电前先结束旧通话并记录结束原因；多条等待请求不会互相覆盖，同一事件重复请求合并展示。
- [ ] 接听事件来电或普通来电后复用既有通话组件，默认收起为地图悬浮通话条；点击“展开”后打开原通话面板，并保留成员管理、静音和结束通话能力。
- [ ] 待处理来电卡片固定展示来电类型、来电人名称或车牌号、所属项目、来电时间，不重复或额外展示其他字段。
- [ ] 来电请求列表提供“通话记录”按钮，无待接请求时仍可查看；打开不触发接听，不改变事件状态；等待请求仍独立计时。
- [ ] 统一记录包含事件呼入、事件外呼、普通通话及未接通结果；通话方向、业务关联和通话结果可独立组合筛选；同次通话在不同入口引用同一记录。
- [ ] 通话记录提供“通话对象”输入框，对参与人姓名进行包含式模糊查询；提供开始日期和结束日期组成的时间范围筛选框，支持仅填写一端；默认按呼叫时间倒序，每页 10 条，可切换 20/50 条，并以一个连续完整列表展示记录。
- [ ] 记录弹窗内容内部滚动，小屏列表可横向滚动，筛选可换行；空结果有明确提示和重置入口；关联事件点击后定位事件并切换通话记录，不接单、不恢复事件；已完成事件无回拨入口；普通通话回拨不关联前台事件。

## 附录 A：统一组件规范

| 组件 | 使用场景 | 业务要求 |
| --- | --- | --- |
| 状态标签 | 事件卡片、事件详情、队列。 | 明确区分事件状态与话务员工作状态，不可混用。 |
| 图片预览 | 事件证据。 | 支持查看上报事件图片；仅当前处理人且事件处于处理中或挂起中时，预览中提供补充信息、派发任务和标记无效按钮；未接单、已完成或无效事件不展示处理按钮。补充信息、标记无效在图片右侧展开表单，派发任务复用资源派发流程；视频支持待确认。 |
| 事件详情操作栏 | 非已完成任务详情已打开时卡片固定底部操作区。 | 待处理事件仅展示“开始处理”；接单成功后，当前处理人可使用语音通话、派发任务、标记无效和挂起，补充信息操作设置于补充信息卡片标题栏右侧。挂起中直接保留补充、语音通话、派发任务和标记无效等可操作入口，不展示“恢复处理”；实际发起后续处理时自动回到处理中。已完成任务隐藏补充信息操作及整个操作栏，不展示更多操作。详情内容独立滚动，操作栏始终停靠在卡片底部；详情卡片在常规桌面宽度为 456px、1366px 断点为 416px，采用 20px 标题、16px 分组标题、14px 正文。 |
| 二次确认弹窗 | 标记无效、确认分配。 | 展示操作影响；未确认不改变状态；取消、次操作与确认操作在底部右侧相邻成组，确认操作位于最右侧，按钮间距 12px。 |
| 消息提示 | 接收、保存、挂起、沟通、分配等操作。 | 成功提示结果；失败提示原因并保留可继续操作的数据。 |
