## 1. 业务背景与使用角色
### 1.1 业务背景
话务中心面向话务员，以事件为中心接收巡查人员通过车辆套件上报的事件。话务员查看证据、判别和补充信息；存在疑问时发起沟通或挂起；确认有效后分配处置资源。已派发事件同步至环卫云平台动态任务跟踪。当前范围仅处理车载监控采样事件，话务中心视角的事件发现类型统一记为人工。
### 1.2 使用角色
| 角色 | 职责 | 数据范围 |
| --- | --- | --- |
| 话务员 | 接收事件、核实判别、补充信息、发起沟通、挂起、分配资源、查看后续流转。 | 已分配或推送至本人处理范围的车载监控采样事件；具体范围待确认。 |
| 任务接收人/处置人员 | 接收环卫云动态任务并现场处置。 | 非本模块直接操作角色。 |
### 1.3 核心目标与价值
| 目标维度 | 说明 |
| --- | --- |
| 及时接收 | 让待判别、待分配阶段的事件进入话务员队列并按优先级呈现。 |
| 快速判别 | 以事件证据和沟通结果支持有效/无效判断及信息补充。 |
| 高效分配 | 基于责任区域、距离和任务量推荐可用资源，并支持人工调整。 |
| 闭环可追踪 | 派发后由环卫云动态任务跟踪事件处置进度。 |

## 3. 功能详细设计
### 3.1 F01 事件接收与队列
#### 3.1.1 功能目标与范围
| 项目 | 说明 |
| --- | --- |
| 功能目标 | 使话务员集中接收并处理待判别、待分配阶段的车载监控采样事件。 |
| 使用角色 | 话务员。 |
| 触发条件 | 话务员开启任务接收；接收到符合当前处理范围的事件。 |
| 功能边界 | 不承接监控中心、机器人采样、AI 监控采样、对讲机采样、无人机采样及第三方来源的事件。 |
| 成功结果 | 事件进入对应话务员队列；默认不展开详情，话务员选择事件后进入详情处理。 |
#### 3.1.2 数据与字段规则
| 展示字段 | 业务含义 | 数据来源/口径 | 空值处理 |
| --- | --- | --- | --- |
| 项目名称 | 事件所属项目。 | 上报事件。 | 待确认。 |
| 处理状态 | 话务员工作状态。枚举值：待处理、处理中、挂起中、已完成。 | 话务中心。 | 不可为空。 |
| 车牌号 | 上报车辆标识。 | 车载监控采样事件。 | 待确认。 |
| 用户名 | 上报用户/巡查员名称。 | 上报事件。 | 待确认。 |
| 上报时间 | 事件上报时间。 | 上报事件。 | 不可为空。 |
| 事件地点 | 事件标准地点。 | 上报事件。 | 待确认。 |
#### 3.1.3 业务规则与状态变化
| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| --- | --- | --- | --- |
| Q-01 | 事件进入话务中心 | 仅接收事件来源为车载监控采样的事件；事件发现类型统一展示为人工。 | 生成或更新话务员工作项。 |
| Q-02 | 事件状态为待判别 | 事件应进入话务员待处理队列；话务员选择事件卡片或地图事件点即视为接收，并进入处理中。 | 事件：待判别；话务员：待处理→处理中。 |
| Q-03 | 话务员处理中 | 查看证据、判别、补充信息、语音沟通期间维持处理中。 | 话务员：处理中。 |
| Q-04 | 事件已派发 | 话务员工作结束；后续现场处置不再占用默认待办队列。 | 事件：待处理；话务员：已完成。 |
#### 3.1.4 交互流程
1. 话务员开启任务接收，系统加载其处理范围内的车载监控采样事件。
2. 系统按话务员工作状态归入待处理、处理中、挂起中、已完成队列，并应用第 4.2 节排序规则。
3. 默认不展开事件详情。话务员选择事件卡片或地图事件点，系统展开详情，且该选择即视为开始处理，话务员工作状态变为处理中；不设置单独的“开始处理”操作。
4. 成功：列表与详情同步刷新；失败：保留当前列表并提示接收或加载失败原因。
#### 3.1.5 异常处理
| 异常场景 | 系统处理 | 用户反馈 | 恢复方式 |
| --- | --- | --- | --- |
| 无符合范围的事件 | 展示空状态。 | 提示当前暂无待处理事件。 | 保持任务接收状态，等待新事件。 |
| 事件数据加载失败 | 不改变已有队列数据。 | 提示加载失败。 | 重新加载。 |
### 3.2 F02 事件详情与判别
#### 3.2.1 功能目标与范围
| 项目 | 说明 |
| --- | --- |
| 功能目标 | 让话务员依据事件原始信息和图片证据完成判别或补充信息。 |
| 使用角色 | 话务员。 |
| 触发条件 | 在事件队列中选择事件。 |
| 功能边界 | 不提供车辆运行状态检查。详情默认聚焦证据、发生时间、事件状态、发现方、地点、关联任务和处置节点；不默认展示事件判别字段、发现类型、事件来源、事件描述、经纬度。事件类型、性质和描述仅在补充信息表单及补充记录中呈现。 |
| 成功结果 | 有效事件进入待分配；无效事件直接闭环；补充信息保存至事件。 |
#### 3.2.2 数据与字段规则
| 字段 | 业务含义 | 数据来源/取值规则 | 空值处理 |
| --- | --- | --- | --- |
| 问题类型 | 原始问题类型。未清洗时显示未知；示例值为明显垃圾。 | 上报事件。 | 显示未知。 |
| 事件发生时间 | 事件实际发生或上报记录的发生时间。 | 上报事件。 | 待确认。 |
| 事件状态 | 全流程处置状态。枚举值：待判别、待分配、待处理、处理中、待核查、已完成。 | 事件。 | 不可为空。 |
| 事件发现方 | 具体的人、车或设备，例如巡查员张三、独角兽 10032、摄像头 A。 | 上报事件。 | 待确认。 |
| 事件图片 | 事件证据图片。 | 上报事件。 | 待确认。 |
| 事件地点 | 事件标准地点。 | 上报事件。 | 待确认。 |
| 详细地点 | 具体点位或地址补充。 | 上报事件。 | 待确认。 |
| 关联任务 | 派发后关联的环卫云动态任务。 | 环卫云平台。 | 未派发时为空。 |
| 处置节点 | 六阶段处置链路，当前节点高亮。 | 事件状态。 | 不可为空。 |
| 补充信息 | 话务员判别结果、事件类型和描述的留痕，展示时间、来源和内容。 | 话务员补充或图片判读。 | 无记录时提示可补充。 |
#### 3.2.3 业务规则与状态变化
| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| --- | --- | --- | --- |
| J-01 | 查看事件详情 | 处置节点始终展示六阶段，当前事件状态高亮。 | 无。 |
| J-02 | 原始描述为空 | 话务员可依据图片识别或与巡查员沟通结论补充事件性质、事件类型、事件描述。 | 更新补充字段。 |
| J-03 | 判别为有效事件 | 进入分配环节。 | 事件：待判别→待分配。 |
| J-04 | 判别为无效事件 | 事件流程直接闭环。 | 最终事件状态口径待确认。 |
| J-05 | 保存并派发任务 | 保存有效事件的补充信息后，直接打开资源推荐与派发界面；补充记录持续保留在事件详情。 | 事件维持待分配，进入分配操作。 |
#### 3.2.4 交互流程
1. 话务员进入详情后查看事件原始信息、图片、处置节点和关联任务。
2. 话务员补充事件性质、事件类型或事件描述；补充结果按时间留存在详情中。有疑问时可进入沟通或挂起流程。
3. 话务员判别有效，系统校验判别结果并将事件转入待分配；可选择“保存并派发任务”直接进入资源选择。判别无效，系统执行闭环确认。
4. 成功：保存补充信息并刷新详情、队列和流转信息；失败：保留已输入内容并提示失败原因。
#### 3.2.5 外部依赖
| 依赖模块/服务 | 输入 | 输出 | 调用时机 | 失败处理 |
| --- | --- | --- | --- | --- |
| 车载监控采样 | 事件基础信息、图片、位置和发现方。 | 事件详情。 | 事件接收、详情加载。 | 保留可用信息并提示缺失。 |
### 3.3 F03 沟通与挂起
#### 3.3.1 功能目标与范围
| 项目 | 说明 |
| --- | --- |
| 功能目标 | 为信息核实和资源确认提供通话入口，并防止等待中的事件被遗漏。 |
| 使用角色 | 话务员。 |
| 触发条件 | 事件信息不清楚、需要向巡查员核实，或需要与候选资源确认。 |
| 功能边界 | 本期仅定义发起沟通和挂起的业务需求；通讯方式、建群能力及记录字段待确认。 |
| 成功结果 | 沟通结论可用于补充事件信息或资源选择；挂起事件按提醒规则回流。 |
#### 3.3.2 数据与字段规则
| 字段 | 业务含义 | 数据来源/取值规则 | 空值处理 |
| --- | --- | --- | --- |
| 沟通对象 | 巡查员/上报人或候选人员、车辆资源。 | 当前事件及候选资源。 | 至少选择一名对象；车辆通话能力待确认。 |
| 挂起提醒时间 | 需要再次关注该事件的时间。 | 话务员设置。 | 挂起时不可为空。 |
| 挂起时长 | 自事件进入挂起中起累计的时长。 | 系统计算。 | 不可为空。 |
#### 3.3.3 业务规则与状态变化
| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| --- | --- | --- | --- |
| C-01 | 发起沟通 | 沟通不改变事件全流程状态；话务员工作项保持处理中。 | 话务员：处理中。 |
| C-02 | 挂起事件 | 信息不足、等待车端回复或等待确认时可挂起。 | 话务员：处理中→挂起中；事件保持待判别或待分配。 |
| C-03 | 挂起排序 | 按挂起到期/提醒时间升序，再按挂起时长降序排序。 | 队列顺序更新。 |
| C-04 | 通话进行中收起窗口 | 通话持续进行，窗口收起为地图上的悬浮通话条；话务员可继续查看地图、详情和操作区，并可随时展开或结束通话。 | 不改变事件状态和通话计时。 |
#### 3.3.4 交互流程
1. 话务员在事件详情或资源候选列表中选择沟通对象并发起沟通。
2. 话务员依据沟通结论继续补充事件信息、选择资源，或设置提醒时间将事件挂起。
3. 系统保存挂起提醒并将事件移入挂起中队列。
4. 成功：提示操作成功并刷新对应队列；失败：不改变原工作状态并提示失败原因。
#### 3.3.5 异常处理
| 异常场景 | 系统处理 | 用户反馈 | 恢复方式 |
| --- | --- | --- | --- |
| 未选择沟通对象 | 阻止发起沟通。 | 提示选择对象。 | 选择对象后重试。 |
| 未设置提醒时间即挂起 | 阻止挂起。 | 提示设置提醒时间。 | 补充提醒时间后重试。 |
| 通讯服务不可用 | 不改变事件状态和补充信息。 | 提示通讯不可用。 | 重试或改用后续确认的沟通方式。 |
### 3.4 F04 事件分配
#### 3.4.1 功能目标与范围
| 项目 | 说明 |
| --- | --- |
| 功能目标 | 将已判别有效的事件分配给合适的在线资源，并同步至环卫云动态任务。 |
| 使用角色 | 话务员。 |
| 触发条件 | 事件状态为待分配。 |
| 功能边界 | 人员为主要分配资源，车辆仅作为可增加的补充资源；不定义现场任务执行规则。 |
| 成功结果 | 创建关联动态任务，事件进入待处理，话务员工作项完成。 |
#### 3.4.2 使用条件与权限
| 角色 | 可执行操作 | 数据范围 | 前置条件 |
| --- | --- | --- | --- |
| 话务员 | 查看推荐资源、发起沟通、人工调整、确认分配。 | 当前事件可用的人员及可选车辆资源。 | 事件已判别为有效且处于待分配。 |
#### 3.4.3 数据与字段规则
| 字段 | 业务含义 | 数据来源/取值规则 | 空值处理 |
| --- | --- | --- | --- |
| 候选人员 | 系统推荐的可分配人员。 | 人员组织、责任区域、在线和任务信息。 | 无候选时按待确认的兜底规则处理。 |
| 可选车辆资源 | 可增加到任务的车辆资源。 | 车辆在线和任务信息。 | 可不选择。 |
| 责任区域 | 候选资源与事件地点的责任范围匹配信息。 | 组织/区域关系。 | 待确认。 |
| 当前距离 | 候选资源与事件位置的当前距离。 | 位置服务。 | 待确认距离口径。 |
| 当前任务量 | 候选资源当前承接任务数量。 | 任务系统。 | 待确认统计口径。 |
| 在线情况 | 人员或车辆资源在线状态。 | 在线服务。 | 不在线资源的展示与可选性待确认。 |
#### 3.4.4 业务规则与状态变化
| 规则编号 | 触发条件 | 业务规则 | 数据/状态变化 |
| --- | --- | --- | --- |
| A-01 | 加载候选资源 | 系统以人员为主推荐资源；车辆仅作为可添加的补充资源。 | 展示候选资源。 |
| A-02 | 候选资源排序 | 依次按责任区域、当前距离、当前任务量排序。在线情况作为候选资源信息和选择依据。 | 候选顺序更新。 |
| A-03 | 资源确认 | 话务员可先通话确认，并可依据沟通结果手动调整资源选择。 | 保存最终选择。 |
| A-04 | 分配成功 | 创建关联动态任务并同步环卫云。 | 事件：待分配→待处理；话务员：处理中→已完成。 |
#### 3.4.5 交互流程
1. 话务员对待分配事件发起分配，系统加载人员推荐结果和可选车辆资源。
2. 系统按责任区域、当前距离、当前任务量的顺序排列候选人员；话务员可查看在线情况并与资源沟通。
3. 话务员选择最终人员，可按实际需要增加车辆资源，确认分配。
4. 系统创建动态任务并关联事件；成功后刷新事件状态和话务员队列，失败时保留选择结果并提示失败原因。
#### 3.4.6 外部依赖
| 依赖模块/服务 | 输入 | 输出 | 调用时机 | 失败处理 |
| --- | --- | --- | --- | --- |
| 组织与责任区域服务 | 事件地点、资源信息。 | 责任区域匹配。 | 候选资源推荐。 | 推荐失败时的人工选择能力待确认。 |
| 位置服务 | 事件经纬度、资源当前位置。 | 当前距离。 | 候选资源排序。 | 距离不可用时的排序口径待确认。 |
| 资源在线与任务服务 | 人员/车辆标识。 | 在线情况、当前任务量。 | 候选资源推荐。 | 显示数据获取失败提示。 |
| 环卫云平台 | 事件、最终资源选择。 | 动态任务标识及任务状态。 | 确认分配。 | 不改变事件和话务员完成状态，支持重试。 |
### 3.5 F05 处置进度查看
#### 3.5.1 功能目标与范围
| 项目 | 说明 |
| --- | --- |
| 功能目标 | 让话务员在详情中了解已派发事件的全流程处置进度。 |
| 使用角色 | 话务员。 |
| 触发条件 | 查看已完成话务工作项或已有关联任务的事件详情。 |
| 功能边界 | 仅展示关联任务和事件状态，不在话务中心执行现场处置。 |
| 成功结果 | 可查看事件从待处理、处理中、待核查到已完成的后续状态。 |
#### 3.5.2 数据与字段规则
| 展示字段 | 业务含义 | 数据来源/口径 | 空值处理 |
| --- | --- | --- | --- |
| 事件状态与处置节点 | 事件全流程状态和当前阶段。 | 事件及环卫云状态回写。 | 不可为空。 |
| 关联任务 | 环卫云动态任务引用。 | 环卫云平台。 | 未派发时为空。 |
| 流转信息 | 事件在话务处理和后续处置中的状态变化信息。 | 事件/环卫云平台。 | 具体记录字段待确认。 |
#### 3.5.3 交互流程
1. 话务员打开事件详情，系统加载关联任务、事件状态和处置节点。
2. 对已派发事件，系统展示环卫云回写的后续状态。
3. 成功：展示最新状态；失败：保留最近一次可用状态并提示刷新失败。

## 4. 业务规则汇总
### 4.1 事件范围与来源口径
| 规则项 | 规则 |
| --- | --- |
| 事件来源范围 | 话务中心仅处理车载监控采样事件，巡查车归入该来源。 |
| 事件发现类型 | 话务中心处理的事件统一记为人工。 |
| 非范围来源 | 监控中心、机器人采样、AI 监控采样、对讲机采样、无人机采样、第三方来源不在当前范围。 |
### 4.2 状态流转与队列排序
```text
事件：待判别 -> 待分配 -> 待处理 -> 处理中 -> 待核查 -> 已完成
话务员：待处理 -> 处理中 -> 挂起中（等待） -> 处理中 -> 已完成
有效判别：待判别 -> 待分配；分配成功：待分配 -> 待处理，话务员 -> 已完成
无效判别：事件直接闭环（最终状态口径待确认）
```
| 话务员队列 | 排序规则 |
| --- | --- |
| 待处理 | 事件优先级降序，再按上报时间升序；重点项目或重点区域命中高优规则。 |
| 处理中 | 待话务员动作优先，再按长时间无更新优先，最后按开始处理时间升序。 |
| 挂起中 | 挂起到期/提醒时间升序，再按挂起时长降序。 |
| 已完成 | 按话务完成时间降序。 |
### 4.3 分配规则
| 规则项 | 规则 |
| --- | --- |
| 推荐主体 | 人员为首要推荐资源，车辆为可选补充资源。 |
| 候选依据 | 结合人员、车辆在线情况。 |
| 排序顺序 | 责任区域 → 当前距离 → 当前任务量。 |
| 人工调整 | 话务员可发起通话并按实际沟通结果调整选择。 |
### 4.4 数据补充与闭环规则
| 规则项 | 规则 |
| --- | --- |
| 可补充信息 | 事件性质、事件类型、事件描述；保存后以时间、来源和内容回写为详情中的补充记录，可作为派发任务的前置信息。 |
| 补充依据 | 事件图片识别结果或与巡查员通讯的结论。 |
| 原始描述 | 允许为空。 |
| 无效事件 | 标记为无效事件后直接闭环。 |

## 8. 验收标准
- [ ] 仅车载监控采样事件可进入话务中心；详情中的发现类型为人工、事件来源为车载监控采样。
- [ ] 事件卡片展示项目名称、话务员处理状态、车牌号、用户名、上报时间和事件地点。
- [ ] 事件详情展示本 PRD 第 3.2.2 节已确认字段，且当前处置节点与事件状态一致。
- [ ] 待判别事件进入话务员待处理队列，接收后变为处理中。
- [ ] 待处理、处理中、挂起中、已完成队列按第 4.2 节规则排序。
- [ ] 话务员能够补充事件性质、事件类型和事件描述，并可将事件标记为有效或无效。
- [ ] 无效事件执行直接闭环；最终事件状态按确认后的口径保存。
- [ ] 话务员能够发起沟通、设置挂起提醒，并在挂起队列中按提醒时间排序。
- [ ] 资源推荐以人员为主，按责任区域、当前距离、当前任务量排序，且支持选择补充车辆资源和人工调整。
- [ ] 分配成功后，事件转为待处理、话务员工作项转为已完成，并在环卫云生成关联动态任务。
- [ ] 已派发事件可在详情中查看关联任务和环卫云回写的后续处置状态。
